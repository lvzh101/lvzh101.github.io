WSL2 连接 Windows 的 FlClash 代理：配置、验证与排错

最近在 WSL2 里维护 Hexo 博客时，我遇到了 Node.js 下载连接超时的问题。Windows 上已经开启了 FlClash，但 WSL2 里的命令行工具仍然无法稳定访问下载源。

这次我把 WSL2 连接 Windows 代理的过程整理下来，包括临时配置、终端自动加载、开关命令，以及实际连接验证。最终可以在任意目录使用 proxy set、proxy unset、proxy status 和 proxy test 管理代理。

一、我的环境与连接原理

这次实际使用的环境如下：

项目 配置
Windows Windows 10
Linux Ubuntu 24.04，运行于 WSL2
WSL2 网络模式 NAT
Windows 代理软件 FlClash
HTTP／混合代理端口 7890
终端 Bash

本文的地址获取方式适用于 WSL2 的 NAT 网络模式。 如果使用镜像网络，需要根据实际网络情况调整代理地址。

在我的环境中，Windows 系统代理地址是 127.0.0.1:7890。这个地址在 Windows 内指向 Windows 自己，而在 WSL2 的 NAT 网络中，127.0.0.1 指向 WSL2 自己。

我测试时的 Windows 网关地址为 172.18.32.1。这个地址可能随着 WSL2 重启而改变，所以后面的配置会动态读取网关。

3. 确认本机代理端口

系统代理界面中的 127.0.0.1:7890 只说明 Windows 应用使用哪个地址，不能单独证明 WSL2 能访问该端口。还需要确认代理程序允许其他网络接口接入，并从 WSL2 实际测试。

这里的 https_proxy 也使用 http://，因为连接的是 HTTP 代理端口；访问 HTTPS 网站时，客户端通常通过 HTTP CONNECT 建立隧道。变量名里的 HTTPS 表示目标请求的协议，不要求代理地址也写成 https://。

3. 日常使用

命令 作用
proxy set 重新获取网关并开启当前终端代理
proxy unset 关闭当前终端代理
proxy status 查看代理地址和绕过列表
proxy test 测试 Google、GitHub、Node.js 和 npm 仓库

这些开关作用于执行命令的终端及其后续子进程。已经打开的其他终端不会同步切换；需要禁用自动开启时，可以从 ~/.bashrc 中移除 proxy set --quiet 那一行。
